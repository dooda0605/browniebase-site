# Handoff: 바다퐁(Badapong) 앱 UI 리디자인 — 심해 다크 방향

## Overview

바다퐁 Flutter 앱의 주요 7개 화면을 "깊은 심해 + 미세한 물결" 방향으로 리디자인했습니다.
`theme.dart`의 기존 토큰(ocean/teal/deep/등급색)은 **그대로 유지**하고, 정보구조·위계·간격만 재구성했습니다.

핵심 변경 축 4개:

1. **헤드룸 회수** — 화면 상단을 점유하는 상시 컨트롤을 줄이고 콘텐츠를 첫 화면으로 끌어올림
2. **등급 발광** — 채운 사각 배지 + 카드 전체 그라데이션 → 링 오브 + 좌측 발광 바 (카드 바탕은 중립)
3. **판단 먼저** — 결론 문장을 스크롤 위로, 부가 섹션은 목록 행으로 접기
4. **다크 대비 수정** — 다크 모드에서 안 읽히는 ocean500/teal600/#0A7C46 텍스트를 밝은 짝으로 교체

## About the Design Files

이 폴더의 `.dc.html` 파일들은 **HTML로 만든 디자인 레퍼런스**입니다 — 의도한 모양과 동작을 보여주는 프로토타입이며, 그대로 복사해 쓰는 프로덕션 코드가 아닙니다.

작업은 이 HTML 디자인을 **기존 Flutter 코드베이스 안에서 재현**하는 것입니다. Flutter 3.41+ / Riverpod / go_router / Material 3 구조와 `AppTheme` 토큰을 그대로 쓰고, HTML의 픽셀값은 Flutter 위젯 속성으로 옮기면 됩니다.

각 파일에는 화면당 두 개의 프레임이 있습니다:

- **왼쪽 (a)** = 현재 앱 화면의 재현. 소스 코드에서 값을 읽어 만든 것으로, **비교 기준**입니다. 구현 대상이 아닙니다.
- **오른쪽 (b)** = 리디자인. **이쪽을 구현합니다.**
- 오른쪽 열의 텍스트 노트 = 왜 바꿨는지 + 소스의 어느 부분이 문제였는지

## Fidelity

**High-fidelity (hifi)**. 색·타이포·간격·반경·그림자가 모두 최종값입니다.
`(a)` 프레임의 모든 값은 실제 소스 파일에서 읽어 온 것이므로, 현재 코드와 대조하면 정확히 무엇이 달라지는지 확인할 수 있습니다.

한 가지 예외: `.dc.html`은 웹이라 `Material Symbols Rounded` 폰트로 아이콘을 그렸습니다. Flutter에서는 대응하는 `Icons.*`를 쓰면 됩니다 (아이콘 이름은 동일: `waves` → `Icons.waves`).

### 데이터: `description_short` 신규 필드 (선행 작업 권장)

목록에서 설명이 잘리는 문제는 레이아웃이 아니라 데이터 쪽에서 푸는 게 맞습니다.

**측정값** — 홈 스팟 카드에서 설명이 쓰는 폭은 약 234px입니다 (카드 내부 324 − 등급 오브 44 − 하트 20 − 간격 26). 12px 한글은 글자당 약 12px이므로 **한 줄 19자 · 2줄 38자**가 상한입니다.

**목록에서 잘리는 것 자체는 문제가 아닙니다.** 항목은 미리보기이고 탭하면 전문이 있는 상세로 갑니다 (상세에서 잘리는 건 문제입니다 — 더 갈 곳이 없으므로. 그래서 상세는 전문 블록으로 되살렸습니다). 문제는 **잘린 앞 38자에 정보가 남는지**입니다.

```
나쁨: "수심이 완만한 몽돌 해변. 방파제 안쪽은 파도가 거의 없어 초급…"   ← 핵심이 뒤에 있음
좋음: "초급 입문용 몽돌 해변. 방파제 안쪽은 파도가 거의…"              ← 앞 20자로 판단 가능
```

**작업:**

1. `spots` 테이블에 `description_short_ko` / `description_short_en` 추가 (varchar 40)
2. `tools/llm_analyze_spot_meta_v2.py`의 출력 스키마에 `description_short` 추가.
   프롬프트 지시: *40자 이내, 첫 문장에 활동 적합도와 지형 특징을 담고, 편의시설·접근성은 넣지 않는다* (그건 별도 필드에 있습니다)
3. `models/spot.dart`에 `localizedDescriptionShort(langCode)` 추가 — 값이 없으면 `localizedDescription`으로 폴백
4. `spot_card.dart`(홈·검색·보관함)는 short를, `spot_detail_screen.dart`는 전문을 사용
5. 10개 언어 모두 필요합니다. 기존 `description_ko/en` 2종만 있는 구조라, 다국어 확장 계획과 함께 결정할 것

이 필드가 없으면 4번은 그냥 전문을 `maxLines: 2`로 두면 됩니다 — 지금 동작과 같습니다.
